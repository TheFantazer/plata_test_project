# Сервис котировок валют

Тестовое задание Plata Go Engineer. Сервис принимает запрос на обновление курса, возвращает ID заявки и получает курс в фоне. Результат можно запросить по ID или получить последнюю успешно обновлённую котировку валютной пары.

Поддерживаются валюты `USD`, `EUR` и `MXN`. Курсы запрашиваются у [Frankfurter](https://frankfurter.dev/) и сохраняются в БД (PostgreSQL).

## Запуск

Из корня проекта выполните:

```bash
docker compose up -d --build
```

Compose поднимет PostgreSQL 18, дождётся его готовности, применит ещё не выполненные миграции и запустит приложение. HTTP API - `localhost:8080`, PostgreSQL — `localhost:5432`. Контейнер `migrate` завершится с кодом `0` после применения миграций.

Проверка запуска и просмотр логов:

```bash
curl -i http://localhost:8080/healthz
docker compose logs -f app
```

`GET /healthz` возвращает `200 OK`, если HTTP-сервер отвечает. Остановить сервис:

```bash
docker compose down
```

## API

Валютную пару нужно передавать в верхнем регистре в формате `BASE/QUOTE`, например `EUR/MXN`. Одинаковые валюты в паре не допускаются.

### Запросить обновление котировки

```bash
curl -i -X POST http://localhost:8080/v1/quote-updates \
  -H 'Content-Type: application/json' \
  -d '{"pair":"EUR/MXN"}'
```

Ответ `202 Accepted`:

```json
{"id":1}
```

Обработчик не ждёт ответа внешнего API: заявку забирает фоновый воркер. Пока для пары уже есть заявка в состоянии `pending` или `processing`, повторный POST возвращает её ID. После завершения этой заявки новый POST создаёт новую.

### Получить заявку по ID

Используйте **число из ответа POST** вместо `1` в примере:

```bash
curl -i http://localhost:8080/v1/quote-updates/1
```

Пока воркер не завершил обработку, ответ `200 OK` выглядит так:

```json
{"id":1,"pair":"EUR/MXN","status":"processing"}
```

После успешного обновления:

```json
{"id":1,"pair":"EUR/MXN","status":"completed","price":"20.5250000000","fetched_at":"2026-10-14T09:20:42Z"}
```

`price` возвращается строкой, чтобы не терять точность десятичного значения. `fetched_at` — время сохранения полученной котировки в UTC. При ошибке внешнего API заявка получает статус `failed` и поле `error_message`. Для `pending` и `processing` поля `price` и `fetched_at` отсутствуют.

### Получить последнюю котировку пары

```bash
curl -i 'http://localhost:8080/v1/quotes/latest?pair=EUR/MXN'
```

Ответ `200 OK` имеет тот же формат, что и завершённая заявка по ID. Маршрут выбирает последнюю котировку со статусом `completed` по времени `fetched_at`. Если новая заявка ещё обрабатывается, ранее полученная котировка остаётся доступной. Если успешной котировки для пары ещё нет, возвращается `404 Not Found`, даже когда существует заявка `pending` или `processing`.

### Ошибки

| Код | Когда возвращается |
| --- | --- |
| `400` | Некорректный JSON, валютная пара или ID заявки |
| `404` | ID не найден или для пары ещё нет успешной котировки |
| `413` | Тело POST-запроса больше 4 KiB |
| `500` | Внутренняя ошибка сервиса или базы данных |

Ошибки возвращаются текстом; успешные ответы API — в JSON.

## Реализованные дополнительные пункты задания

- **Unit-тесты:** проверяют HTTP-обработчики, разбор ответов Frankfurter и повторы запросов воркера. Тесты используют заглушки и локальный тестовый HTTP-сервер; реальный внешний API и PostgreSQL для их запуска не нужны.
- **Контейнеризация:** `Dockerfile` собирает Go-приложение, а `docker-compose.yml` запускает приложение, БД и одноразовый контейнер миграций.
- **Идемпотентность обновления:** P.S. Надеюсь в ТЗ имелась ввиду идемпотеность обработки задач, а не HTTP-идемпотентность через Idempotency-Key. Реализовал так: повторный POST для той же пары возвращает ID существующей заявки, пока она находится в `pending` или `processing`. Частичный уникальный индекс в PostgreSQL не допускает две активные заявки для одной пары даже при одновременных запросах. После перехода заявки в `completed` или `failed` новый POST создаёт новую заявку.

Спецификация Swagger/OpenAPI не добавлена: это необязательный пункт задания.
